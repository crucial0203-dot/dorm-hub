# 骗子博弈 · 国内网络环境联机指南

## 默认配置（已内置）

| 配置项 | 默认值 |
|---|---|
| 传输层 | **MQTT 中央中继**（默认 EMQX 国内节点 `broker-cn.emqx.io`，基于 WebSocket；可切换备选）|
| 房间同步 | 房主广播 `STATE_UPDATE` 至 `lg/<房间>/state`，所有客户端订阅 `lg/<房间>/#` |
| 命令通道 | 客户端发 `lg/<房间>/cmd/<客户端id>`，房主定向回复 |
| 直连/穿透 | 已弃用（WebRTC P2P / PeerJS / STUN / TURN 不再作为主通道）|

这套配置**对国内局域网、校园网、家庭宽带（公网 IP / 对称 NAT）、公司内网 都能通**。因为没有"两玩家直连"这一步，全部经由公共 broker 转发，**从根上绕开 NAT 打洞**。

## 30 秒开房流程

1. **所有玩家**打开 [https://7o74rwwcytn5z.space.mcode.cn/game/liars-gambit/](https://7o74rwwcytn5z.space.mcode.cn/game/liars-gambit/)
2. **房主**：输入昵称 → 点「✏️ 创建房间」
3. 房主在弹窗里看到 **4 位房间号 + 二维码**，截图/扫码发到寝室群
4. **舍友**：扫码或打开分享链接自动加入；也可手动输入 4 位房间号 + 昵称 → 点「加入」
5. ≥3 人即可开局

> 分享链接形如 `?room=XXXX&broker=<index>`，**加入方会强制与房主使用同一 broker**，避免两端选了不同节点导致互相收不到消息。

## 仍然连不上？

按以下顺序排查：

### 检查 1：浏览器
- **不要用微信内置浏览器**（可能限制 WebSocket）
- ✅ Chrome / Edge / Safari / Firefox 任意现代浏览器
- ✅ 移动端可装 Chrome for Android / Safari iOS

### 检查 2：网络环境
打开浏览器开发者工具 (F12) → Console，看是否有：
- `[peer]` 报错，或 `WebSocket` 连接失败 —— 说明连不上当前 broker
- 创建/加入超时 toast（「连接超时」）—— 中继未在 12s 内 CONNACK 成功
- 可右下角角标切换到其他 broker 后重试

### 检查 3：真实时同步是否生效
- 房主可看到"加入房间"提示与新增玩家
- 舍友进入大厅后应立即看到房主与已加入玩家名单
- 玩家数量与名单应在任何玩家加入/离开时同步更新

### 检查 4：broker 不可达？右下角小角标
页面右下角有一个浮动小角标（`EMQX 国内节点 (默认)`），显示当前 MQTT broker 与连接状态点：
- **绿点**：已连接，房间同步工作正常
- **黄点**：正在连接
- **灰点**：未建房/未加入（待机）
- **红点**：连接失败

点开面板可看到 4 个 broker 备选：
- **EMQX 国内节点**（默认）— 国内可达性好，校园网/家庭宽带推荐
- **EMQX 国际节点**— 国外服务器，海外 ISP 友好
- **Mosquitto 测试 broker**— 国外开源测试节点
- **HiveMQ 公共 broker**— 国外稳定节点

点 **测速全部** 可临时连接每个 broker 验证可达性（8s 超时）。切换选中的 broker 后页面自动刷新，新选择会被记住。

## 同步行为说明（2026-09-23）

- **真实时同步**：玩家加入/离开会在所有在线端即时反映，无需刷新。
- **真就绪**：仅当 MQTT CONNACK 成功后才进入房间；失败会明确超时/报错，不再“假连上”。
- **两端 broker 对齐**：分享/二维码链接携带 `broker` 参数，加入方以链接为准。
- **房主迁移 / 断线重连**：作为 backlog 保留，当前阶段聚焦基础联机稳定。（PeerJS 时代的迁移逻辑已随 P2P 弃用搁置。）

## 工作原理

```
┌──────────┐              ┌────────────────┐              ┌──────────┐
│  房主浏览器 │  pub/sub     │ broker-cn.emqx.io│   pub/sub   │ 舍友浏览器 │
│          │◄────────────►│ （MQTT 中央中继）  │◄───────────►│          │
└──────────┘   lg/<room>/# └────────────────┘  lg/<room>/# └──────────┘
       ▲                                                        ▲
       └─────────── 每个玩家各自连同一 broker，由 broker 转发 ─────┘

  主体流程：
  - 房主创建房间 → 分配 4 位房间号 code
  - 分享链接带 ?room=&broker= → 加入方强制同一 broker
  - 所有玩家订阅 lg/<code>/# ，加入时发 JOIN（未就绪则入队，CONNACK 后 flush）
  - 房主收到 JOIN → 广播 STATE_UPDATE（含玩家名单）到 lg/<code>/state
  - 每个客户端收到广播 → 更新本地 state → 重渲染大厅/对局
```

## 已知限制

- 依赖公共 broker 可用（EMQX 公共免费服务，极端情况下可能有波动）
- 玩的时候别熄屏/切后台（MQTT WebSocket 连接可能超时/重连）
- 公开链接 / 房间号不要发到校外群（防止乱入，房间码提供隐式访问控制）
- 跨网络实测依赖真实用户验证（headless 冒烟已覆盖电离同步主链路）
